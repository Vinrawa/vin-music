# Plan: YT Music Recommendation Post-Processing + Battery Optimization

## Part A: Recommendation Improvements

### Goal
Add language gating + official-only filtering + TasteDNA re-ranking + artist diversity to YouTube Music recommendation results.

### A1. Language gating filter

**Where:** `RecommendationRepository.kt` — `getRelatedSongs()` (line 437), `getSongRadio()` (line 593), `filterHomeSections()` (line 356), `getQuickPicksTasteDnaFallback()` (line 320)

After `inferMetadata()` on each candidate, check `meta.language` against the seed track's language. Skip if different.

For home sections (no seed), use `profile.topLanguages.firstOrNull()`.

### A2. Official-only filter

Same filter points. Add `if (!meta.isOfficial) continue` after content quality filters.

### A3. TasteDNA re-ranking in `getSongRadio()`

Current `getSongRadio()` sorts only by queue diversity (line 605-608). Add TasteDNA scoring before the diversity sort:

```kotlin
val profile = RecommendationManager.buildTasteProfile(db)
val scored = filtered.map { item ->
    val meta = RecommendationManager.getCachedOrInferredMetadata(db, item)
    val tasteScore = RecommendationManager.calculateTasteSimilarity(meta, profile.tasteDNA)
    val officialBonus = if (meta.isOfficial) 0.15 else 0.0
    item to (tasteScore + officialBonus)
}
val sorted = scored.sortedByDescending { it.second }.map { it.first }
```

### A4. Artist diversity: max 3 songs per artist, no dominant artist

**Where:** `getSongRadio()` sequencing (line 610-638), `getRelatedSongs()` selection (line 486-494)

**Rule:** In any 20-song window, no single artist can have more than 3 songs. This applies to ALL artists — not just the seed. If J. Cole has 3, Drake can't have 10. Each artist is capped at 3.

**Implementation:** The sequencing loop uses `artistCount` map. Change the cap from `count < 2` to `count < 3`. The existing "avoid same artist back-to-back" logic stays. This naturally spreads artists across the queue.

For `getRelatedSongs()`, change the same-artist spam cap from 2 to 3 (line 492).

### A5. Same-type enforcement (genre/mood match)

**Where:** `getSongRadio()` (line 605), `getRelatedSongs()` (line 446-477)

The artist cap ensures diversity. The remaining ~17 slots per 20 songs should be same genre/mood as the seed. The existing `calculateTasteSimilarity()` already scores genre (20%), mood (20%), language (15%) heavily. After TasteDNA re-ranking from A3, the top-scoring candidates will naturally be same-type.

Additionally, add a genre floor: if a candidate's genre doesn't match the seed's genre AND it's not from a genre-similar artist, give it a 0.0 genre score (hard penalty) instead of the current 0.1 fallback.

## Part B: Battery Consumption Reduction

### B1. Fix progress polling loop (HIGH impact)

**File:** `PlayerViewModel.kt` lines 498-549

The `while(true)` loop with `delay(180)` runs ~5.5x/sec even when paused. Fix: break out of the loop or suspend when `exoPlayer.isPlaying` is false.

```kotlin
while (isActive) {
    if (!exoPlayer.isPlaying) {
        delay(500) // Sleep longer when paused
        continue
    }
    // ... existing progress update logic
}
```

### B2. Fix untimed WiFi lock (HIGH impact)

**File:** `PlayerSingleton.kt` line 120

`wifiLock?.acquire()` has no timeout. Add a timeout parameter:

```kotlin
wifiLock?.acquire(60_000L) // 60 second max hold
```

### B3. Remove dual wake lock stacking (MEDIUM impact)

**File:** `PlayerSingleton.kt` lines 97, 476

ExoPlayer's `WAKE_MODE_NETWORK` already holds a PARTIAL_WAKE_LOCK. The explicit `acquire()` at line 97 stacks on top. Remove the manual WakeLock and rely on ExoPlayer's built-in lock with `setWakeMode()`.

### B4. Gate logging behind DEBUG flag (MEDIUM impact)

**File:** All files with `Log.d/Log.w/Log.e` calls (~319+ occurrences)

Wrap log calls with `if (BuildConfig.DEBUG)` check. This eliminates string concatenation and IO overhead in release builds.

### B5. Reduce network calls on song transition (MEDIUM impact)

**File:** `PlayerViewModel.kt`, `PlayerSingleton.kt`

Currently fires 20+ HTTP requests per track change. Consolidate:
- Delay lyrics background upgrade by 5 seconds (don't fire immediately)
- Delay color palette extraction until player UI is visible
- Skip description fetch if not needed for current view

### B6. Fix `runBlocking` in InnerTube (LOW impact)

**File:** `InnerTube.kt` line 217

Replace `runBlocking` with proper coroutine scope to avoid blocking IO thread pool threads.

### B7. Add timeouts to orphan coroutine scopes (LOW impact)

**Files:** `AudioFeatureProcessor.kt`, `UpdateManager.kt`, `MusicWidgetProvider.kt`

Add `withTimeout()` or bind scopes to lifecycle to prevent indefinite execution.

### B8. Paginate DiscoverScreen DB loads (LOW impact)

**File:** `DiscoverScreen.kt` lines 222-225

Replace full-table `getAll()` calls with paginated queries (LIMIT 500).
